## 1. 開始之前

- 所有設定都在資源資料夾（`helper_software\`）裡：`software.xml`、`system_tasks.xml`、`tasks\`、各軟體子資料夾。
- 資源資料夾只有系統管理員能寫入（[`DEPLOYMENT.md`](DEPLOYMENT.md) 第 3 節），修改時要以系統管理員身分編輯。
- 建議用 VS Code 加上 XML 擴充功能（Red Hat 的「XML」）編輯：XML 開頭指向同一個資料夾裡的 XSD，打錯欄位名稱或漏掉必填欄位時，編輯器會即時標示。
- XML 一律以 **UTF-8** 存檔（記事本的「UTF-8」或「UTF-8 含 BOM」都可以）。
- 修改前先備份原本的檔案。

**共通規則**（設計第 4.1 節）：

| 規則 | 說明 |
|---|---|
| `id` | 只能用小寫英文、數字、底線，例如 `cpu_z`、`power_008`；同一個檔案內不可重複 |
| 順序 | XML 裡的順序，就是介面顯示與執行的順序 |
| 特殊字元 | 名稱或參數裡的 `&` 要寫成 `&amp;`，`<` 要寫成 `&lt;` |
| 逾時 | 寫在根元素的 `timeout`（秒），整個檔案共用；省略時是 300 秒 |

## 2. 新增軟體

1. 在資源資料夾裡建立子資料夾，例如 `helper_software\CPU-Z\`，放入安裝檔。
2. （選用）在子資料夾裡放圖示，檔名是 `icon.ico`、`icon.png`、`icon.jpg`、`icon.jpeg` 或 `icon.gif`。沒有圖示也可以。
3. 在 `software.xml` 加上一筆 `<item>`，放在想要顯示的位置：

   ```xml
   <item id="cpu_z">
     <name>CPU-Z</name>
     <folder>CPU-Z</folder>
     <executable>cpu-z_2.20.2-en.exe</executable>
     <args>/silent</args>
   </item>
   ```

4. 重新開啟工具，確認沒有出現問題清單，新的軟體出現在清單上（第 5 節）。
5. 在測試機上實際安裝一次。

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | 是 | 見第 1 節的規則 |
| `<name>` | 是 | 介面上顯示的名稱，可以用中文 |
| `<folder>` | 是 | 子資料夾名稱（相對於資源資料夾）；不可以是絕對路徑，也不可含 `..` |
| `<executable>` | 是 | 子資料夾裡的執行檔名稱，只寫檔名 |
| `<args>` | 否 | 參數，**原樣**傳給執行檔。例如 `/D="C:\Program Files\App"` 不會被拆開 |
| `successCodes` | 否 | 視為成功的結束碼，以逗號分隔，預設 `0`。安裝程式以 3010 表示「成功，但需要重新開機」時，寫成 `successCodes="0,3010"`，介面會顯示「成功（3010）」 |
| `copyFirst` | 否 | 預設 `true`，見第 3 節 |

## 3. 什麼時候設定 `copyFirst="false"`

預設（`true`）：執行前先把整個子資料夾複製到「下載」裡的暫存資料夾，從複本執行，全部結束後刪除（[`DEPLOYMENT.md`](DEPLOYMENT.md) 第 4 節）。

符合下列任何一種情況時，設為 `false`，直接從資源資料夾執行：

| 情況 | 例子 | 原因 |
|---|---|---|
| 工具本身就會把檔案複製到桌面或其他位置 | SampleDeskTool（28.6 GB）、SampleDeskFiles | 不用複製兩次，省下時間和空間（DD14） |
| 工具執行後，要繼續從自己的資料夾使用檔案 | 建立的捷徑指向自己的資料夾、執行後才在背景讀取的檔案 | 暫存資料夾在這一輪結束後就會刪除，捷徑會失效 |

```xml
<item id="sample_desk_tool" copyFirst="false">
```

注意：

- 設為 `false` 的軟體在資源資料夾裡執行，所以資源資料夾的權限設定（[`DEPLOYMENT.md`](DEPLOYMENT.md) 第 3 節）更重要。
- 不確定時保留預設值，在測試機上執行一次，確認工具在暫存資料夾刪除後仍然正常。
- `prime95_shortcut.exe` 是否依賴自己的資料夾，尚待 T41 在實機確認。

## 4. 新增系統設定任務

1. 決定放在哪個分類（`<category>`），並取一個 `id`，例如 `power_008`。
2. 在 `tasks\` 裡建立 `power_008.cmd`，檔名和 `id` 相同。從兩個範本擇一複製（原始碼的 `resources\templates\`，或設計文件附錄 A）：

   | 範本 | 用途 |
   |---|---|
   | `stop_on_error.cmd`（失敗即停） | 後面的步驟依賴前面的步驟 |
   | `run_all.cmd`（全部跑完） | 各步驟彼此獨立；有任何一步失敗，整個任務回報失敗（2.0 的行為） |

   ```bat
   @echo off
   rem Helper system task: run every step, fail if any step failed
   rem File name: power_008.cmd / ASCII or ANSI / CRLF line endings
   setlocal
   set "FAILED=0"

   powercfg /change monitor-timeout-ac 0 || set "FAILED=1"
   powercfg /change standby-timeout-ac 0 || set "FAILED=1"

   exit /b %FAILED%
   ```

3. 在 `system_tasks.xml` 對應的分類裡加上 `<task>`：

   ```xml
   <task id="power_008">
     <name>螢幕與待機永不關閉</name>
     <description>插電時不關閉螢幕、不進入待機</description>
   </task>
   ```

4. **以系統管理員身分雙擊 .cmd 測試一次**（在測試機上），確認結果正確、結束時沒有停下來等待輸入。
5. 重新開啟工具，確認沒有出現問題清單，新的任務出現在清單上。

**.cmd 的規則**（設計第 4.4 節）：

| # | 規則 | 不遵守的後果 |
|---|---|---|
| 1 | 成功時 `exit /b 0`；任何一步失敗時以非 0 結束 | 失敗會被判成成功 |
| 2 | 存成 ANSI（Big5），或內容只用英文 | 用 UTF-8 存的話，中文會變成亂碼 |
| 3 | 換行用 CRLF（Windows 的記事本預設就是） | 只有 LF 時，`goto`、`call :label` 可能出錯 |
| 4 | 檔名只用英文小寫、數字、底線，和 `id` 相同 | 找不到腳本，任務不會出現在清單上 |
| 5 | 不使用 `pause` 或任何需要輸入的指令 | 沒有地方讓人輸入 |
| 6 | 不使用 `wmic` | Windows 11 24H2 起預設停用，指令會失敗 |
| 7 | 寫好後以系統管理員身分雙擊測試一次 | 和工具執行時的環境不一致 |

其他提醒：

- `%` 在 .cmd 裡有特殊意義：要印出 `%` 時寫 `%%`；`for` 迴圈的變數寫 `%%i`。
- 設定變數時寫成 `set "X=1"`（加引號）：寫成 `set X=1 || …` 的話，`||` 前面的空白也會存進變數。
- 同一個 .cmd 裡，前面的 `set`、`cd` 會影響後面的步驟；`exit /b` 會結束整個 .cmd。
- 轉換工具產生的 .cmd 寫成 `指令|| set "FAILED=1"`（`||` 前面沒有空白），讓程式收到的參數和 2.0 完全相同；手寫的 .cmd 照範本即可。
- 新增分類：在 `system_tasks.xml` 加上 `<category id="…" name="介面上顯示的名稱">`，裡面放 `<task>`。沒有任何任務的分類不會顯示。

## 5. 修改後的檢查：問題清單

工具啟動時檢查兩個 XML，有問題就跳出問題清單（FR-36），依檔案分組列出嚴重度、項目 `id` 和原因。按「複製」可以把內容貼到訊息或郵件裡。有問題的項目不會出現在清單上，其他項目照常使用。

| 嚴重度 | 意思 |
|---|---|
| 嚴重 | `software.xml` 不存在或無法讀取：工具顯示原因後結束 |
| 錯誤 | 這一筆設定有誤，已略過（或改用預設值） |
| 提醒 | 不影響執行，但可能是打錯字或忘了處理 |

常見的訊息：

| 訊息 | 處理 |
|---|---|
| 找不到執行檔 | `<folder>` 或 `<executable>` 打錯，或檔案還沒放進子資料夾 |
| 找不到腳本 `tasks\<id>.cmd` | .cmd 的檔名和 `id` 不同，或還沒放進 `tasks\` |
| `tasks\xxx.cmd` 沒有登記 | `tasks\` 裡有 .cmd，但 `system_tasks.xml` 沒有對應的 `<task>`：忘了登記，或是應該刪掉的舊檔 |
| 有不認得的元素／屬性，已忽略 | 欄位名稱打錯，例如把 `<args>` 寫成 `<arg>`。這個欄位會被忽略，安裝檔會在沒有參數的情況下執行 |
| id 只能用小寫英文、數字、底線 | 見第 1 節的規則 |
| id 重複 | 只保留第一筆，後面的被略過 |
| 不是合法的 XML：第 N 行第 M 欄 | 標籤沒有關閉、`&` 沒有寫成 `&amp;` 等。依行號、欄號修正 |
| 不是 UTF-8 編碼 | 以 UTF-8 另存 |
| successCodes 必須是以逗號分隔的整數 | 例如 `0,3010`。格式錯誤時這一筆會被略過，避免把失敗誤判為成功 |

完整的檢查規則見設計文件第 6.2 節。

## 6. 從 2.0 的 INI 轉換（FR-21）

在有原始碼的電腦上（需要 Python 3.12）執行：

```bat
python tools\ini2xml.py <2.0 的資源資料夾> <輸出資料夾> --no-copy-first software17,software18
```

- `<2.0 的資源資料夾>`：`config.ini`、`system_optimizations.ini` 所在的資料夾。
- `<輸出資料夾>`：必須是新的或空的資料夾，工具不會覆蓋任何檔案。
- `--no-copy-first`：要設為 `copyFirst="false"` 的軟體（第 3 節），以逗號分隔，寫轉換後的 `id`（也就是 INI 的段落名稱）。
- 轉換後，工具會用 3.0 的讀取方式把結果讀回來，和 INI 逐欄比對。結束代碼 0 代表轉換完成；1 代表無法轉換或比對不一致；2 代表參數錯誤。

**轉換報告**（`ini2xml_report.txt`）列出所有需要人工確認的地方，例如：

- 2.0 本來就不讀的段落與項目、改名的 `id`
- 含有 `%` 的指令：2.0 在命令列模式執行，轉進 .cmd 後是批次檔模式，`%` 的處理方式不同。工具已自動轉換，但沒有定義的環境變數在 .cmd 裡會變成空字串
- 使用 `wmic` 的指令、`exit`／`set`／`cd` 等會影響後面步驟的指令
- 含引號或反斜線的參數：2.0 會拆開，3.0 原樣傳遞

轉換後的每個 .cmd，都要在測試機上以系統管理員身分執行一次。
