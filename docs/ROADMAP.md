## 6. 開發規範

| 項目 | 規範 |
|---|---|
| 分支 | `main` 是預設分支，受保護。每項工作開一個工作分支，完成後開 PR 到 `main`，由你 review 後合併。合併後，下一項工作從最新的 `main` 開新分支 |
| 2.0.x 的分支 | T39 把 `helper.py` 換成 3.0 之後，主線不能再發 2.0.x。所以在 T39 之前，從主線建立 `release/2.0`（2026-10-22，`0c217f2`，版本號 2.0.2）。2.0.x 的修正開 PR 到 `release/2.0`；3.0 也需要的修正，另外開 PR 到 `main` |
| PR | 一個 PR 只做一件事；說明對應的工作編號與需求編號；CI 必須通過 |
| Commit | 一個 commit 只做一件事；訊息寫清楚「改了什麼、為什麼」 |
| 測試 | 新功能先寫測試；重構時先寫測試確認現有行為，再搬移程式碼 |
| 程式碼 | 依設計文件第 13 節：只在邊界捕捉例外，而且一定留紀錄；不使用不指定例外類型的 `except:`；新模組要有型別標註與 docstring |
| 版本號 | 依語意化版本（SemVer）：設定檔格式不相容時升第一碼；新增相容的功能升第二碼；修正錯誤升第三碼 |
| 文件 | 需求或設計有變更時，先修改文件並記錄在修訂紀錄，再改程式 |

## 8. 風險

| 風險 | 影響 | 對策 |
|---|---|---|
| batch 的行為只能在 Windows 上驗證 | .cmd 的規則或執行邏輯有錯 | T36 在 CI 的 Windows 環境執行整合測試 |
| CI 的 Windows 環境無法啟動「需要管理員權限」的執行檔 | 打包後的啟動測試無法自動化 | CI 只驗證打包成功；啟動由實機驗收負責 |
| 工具以管理員權限執行資源資料夾裡的檔案 | 能寫入資源資料夾的人，就能讓自己的程式以管理員權限執行 | T42 的部署說明寫明權限設定 |
| 3.0 的設定檔不相容 | 舊設定無法直接使用 | 提供轉換工具；保留 2.0.x 執行檔可以退回 |
| 暫存資料夾需要大量空間與時間 | 全選時約需複製 18.2 GB（全部都複製則約 48 GB），測試機空間不足時無法執行 | 執行前檢查空間並提示（FR-47）；大型且會自己複製到桌面的工具設為不先複製；T42 的部署說明寫明需要的空間 |
| 安裝程式結束後，子程式仍在使用暫存檔 | 暫存資料夾刪不乾淨 | 全部結束才刪除，被佔用的檔案重試 60 秒；仍刪不掉就列出，下一輪再刪（FR-48） |
| 工具以管理員權限刪除資料夾 | 刪錯會造成無法復原的損失 | 只刪除符合設計第 7.7 節四個條件的資料夾；T46、T36 的測試涵蓋 |
| 有工具依賴自己原本的位置（例如捷徑指向自己的資料夾） | 暫存資料夾刪除後失效 | 已確認 SampleMonitor、FurMark 2 的捷徑不指向自己的資料夾；`prime95_shortcut.exe` 沒有原始碼，T41 實機確認；有問題的項目設為不先複製 |
| 私有 repo 的 CI 執行時間要計費，Windows 比 Linux 貴 | 超出免費額度 | 單元測試在 Linux 上跑；Windows 只在 PR 和 `main` 上跑 |
| 雲端與本機兩邊同時修改 repo | 衝突、覆蓋彼此的修改 | 移到本機後，雲端的工作階段不再推送；本機每次開工前先 `git pull` |
